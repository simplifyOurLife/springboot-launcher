# 架构与交付索引

## 当前状态

仓库当前仅包含书面设计和开源准备材料。后台、MCP 代理、静态面板和自动测试尚未实现；本组文档描述预期行为，不能视作代码审计或测试通过证据。

## 目标结构

| 组件 | 职责 | 边界 |
| --- | --- | --- |
| MCP 代理 | 供 Codex／CC 发现和调用工具，按需连接后台 | 每个客户端会话各自运行，但不拥有 JVM |
| 唯一后台 | 认证、项目检查、进程注册表、操作及日志 | 当前用户所有入口共享，回环监听 |
| 网页面板 | 项目配置、启停、状态和实时日志 | 静态页面，不包含长期后台凭据 |
| JVM | 运行用户信任的 Spring Boot 应用 | 当前用户权限；不是隔离沙箱 |
| 本地状态与日志 | 实例发现、异常诊断和有限日志留存 | 私有状态目录及项目日志，不提交到 Git |

技术方向为 Node.js ESM、官方 MCP Node.js SDK、内置 HTTP／SSE 和测试能力、无需构建的 HTML／CSS／JavaScript。

MCP 代理由私有实例文件取得控制凭据；网页使用短期单次票据交换会话，受保护的查询、日志和操作都需要认证。没有多用户角色或数据库。Windows 私有目录权限须在实现和验收中检查。

## 假设与待验证点

- 目标项目已有可运行产物；缺少或过期时提示用户构建。
- 进程不随聊天结束而停止，但后台异常后的自动接管不进入 MVP。
- Windows 停止操作不保证 JVM 执行优雅关闭钩子。
- CC 终端版通过系统浏览器查看面板；没有假设其支持内嵌网页。
- 所有组件仍未实现，上述边界须有自动测试及真实客户端验收。

目前无邮件功能、定时业务任务、公共可索引网页或内嵌 LLM，因此不生成 emails、cron、seo 文档。外部 MCP 调用能力尚未实现；其实际工具和副作用记录会随实现补充，不能用当前计划充当已存在自动化的审计结果。
