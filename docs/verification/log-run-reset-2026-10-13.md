# 重启后的日志轮次与缺口重置

原实现会在同一服务重启后复用内存事件、旧截断标记，前端也累计缺口状态，导致上一轮日志省略提示持续残留。

修复后，每次服务启动重置内存缓冲和截断标记；日志序号保持单调递增，并在快照与实时事件中携带本轮起始序号。前端识别新轮次后清除旧文本、样式区间和缺口，以本轮起点计算连续性。磁盘日志继续追加；Maven 准备和随后 Java 启动仍属于同一轮日志。

定向验证：`node --test tests/log-store.test.mjs tests/web-state.test.mjs`，9 项通过。新用例覆盖旧轮次超限、重启后空快照、实时事件切换、旧客户端序号重连、新页面完整快照、新轮次再次超限以及磁盘历史保留。修改前该用例复现旧日志仍在缓冲的问题。

当前业务服务仍在运行时不自动中断。后台与页面资源需要重启启动器后加载；真实面板的服务重启结果尚待验收。

## 手动关闭提示

按用户补充要求，日志缺口提示右侧增加关闭按钮，复用中英文“关闭提示”文案。关闭仅隐藏当前轮次提示，不改变真实缺口状态或日志采集；同轮后续输出和重连不重新弹出，新轮次恢复提示资格。定向用例 `node --test --test-name-pattern='手动关闭' tests/web-state.test.mjs` 修改前失败、修改后通过；页面脚本语法检查通过。当前后台仍未重载。
