# 服务管理与彩色日志验证（2026-10-10）

## 实现

- 左侧改为自绘 Spring Boot 风格六边形电源图标、9px 状态圆点、启动 Profile 和三个常驻操作按钮；没有显式 Profile 时显示“应用配置”。
- 移除服务管理菜单，使用指针捕获实现内部拖拽。拖入文件夹与拖回未分组都走同一持久化命令，不移动工程文件；支持 Ctrl+Shift+M／Enter 和 Esc 取消的键盘替代。
- ANSI 在后台逐流增量解析为纯文本与受限样式。支持标准色、256 色、RGB、字重、斜体与下划线，过滤 OSC 和其他控制序列，保持缓存及快照容量约束。检索、复制和轮转文件保持纯文本。
- 启动完成标志按流拼接有限尾部，避免颜色分段导致就绪识别失败；服务状态返回显式 Profile。
- Cookie 名称按后台凭据派生，不同实例互不覆盖。失效时关闭 SSE 重试并显示打开命令；已有页面支持兑换新票据。

## 已执行

- `npm test`：74 项通过，包含新 ANSI／颜色范围／Cookie 隔离测试及彩色启动标志的真实 Node 子进程回归。
- 浏览器实际检查 ANSI 绿、256 色橙、RGB 蓝的计算颜色分别为 rgb(152,195,121)、rgb(255,135,0)、rgb(160,190,255)，关键词高亮优先且周围颜色保留。
- 拖动 inventory-worker 进入“业务服务”，再拖回未分组，检查组计数与服务归属；键盘移动 orders-api 成功，刷新后归属仍在。
- 在 orders-api 保持选中时，通过 auth-service 行的启动、停止、重启按钮控制模拟进程，当前详情保持 orders-api。
- 无会话访问独立空后台显示重新打开指引；在同一页面导航到有效票据后恢复连接并清除 fragment。另一个后台保持连接，未被 Cookie 覆盖。

## 边界

没有执行 Maven、Java 或前端 build，没有调用真实业务服务，没有公开发布。真实 Spring Boot 的完整 ANSI 输出与用户 Codex／Claude Code 客户端仍需人工验收。应用在管道模式可能关闭 ANSI；相关配置说明见[故障排查](../usage/troubleshooting.md)。
