# 桌面入口修复验证

## 原因与修复

此前快捷方式把以反斜杠结尾的安装目录放入双引号参数。Windows 原生启动时将结束引号传入了路径；诊断脚本读取到 Root 的最后字符为 34，即双引号，`GetFullPath` 报非法字符，退出码为 2。

新版快捷方式只传固定面板脚本路径，由脚本自身判断源码根或托管安装目录。图标复用页面品牌图形，ICO 提供 16、24、32、48、64、128、256px 七个尺寸；托管安装将图标放到稳定目录，避免依赖旧版本位置。

## 实际验证

- `tests/shortcut-flow.ps1` 在临时目录创建真实 `.lnk`，读取其目标和参数后调用 Windows PowerShell。源码版与安装版均执行实际面板脚本，Node 替身只记录 `dashboard` 参数，不启动业务服务。
- 覆盖中文、空格、逗号、& 与根目录尾随反斜杠；两个场景均通过，并在 PowerShell 7 与 Windows PowerShell 5.1 下运行。
- 隔离安装流程与 npm 发行文件 dry-run 通过，确认稳定图标被安装且包含在发行白名单中。没有运行 Java、Maven 或工程构建。
- 已替换使用者现有桌面入口。用其真实 TargetPath、Arguments 与 WorkingDirectory 执行，退出码为 0，成功生成面板会话并请求默认浏览器打开；没有重启启动器后台或启停业务服务。

本轮未提交、推送或发布。真实桌面启动验证不同于在 Windows 资源管理器中人工双击验收，仍可由使用者自行体验。

## 页面重新生成时的白图标修复

后续使用暴露了文件解码与 Shell 快捷方式解析的差别。直接读取 ICO 为绿色，但 Shell 读取 `.lnk` 时返回白色图标。通过临时文件逐项对比确认：小尺寸 PNG 图标与 IconLocation 属性内的双引号分别会使当前 Windows Shell 回退为空白图标。

- ICO 的 16–128px 帧改用传统 32 位 BGRA DIB，256px 保留 PNG。
- IconLocation 使用原始路径和图标索引，不加入命令行引号；中文、空格、逗号与 & 的目录均通过 Shell 验证。
- 当前用户应用数据目录保存按图标内容命名的缓存，内容更新时换用新路径；生成后仅通知当前快捷方式更新。
- `tests/shortcut-flow.ps1` 增加 SHGetFileInfo 实际读取 `.lnk` 图标的检查。修复前因白色图标失败，修复后在 PowerShell 7 与 Windows PowerShell 5.1 下通过。
- 通过正式面板的“创建桌面快捷方式”按钮重新生成。页面返回创建成功；Shell 读取实际桌面入口后，32px 图标绿色像素占比由 0 变为约 0.607，确认不再返回空白图标。没有重启后台或启停业务服务。
