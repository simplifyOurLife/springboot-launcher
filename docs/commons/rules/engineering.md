# 工程规范

## 语言与环境

对话、注释、日志、文档和提交信息优先中文；代码标识与必要技术术语保留英文。许可证和来源版权保留原文。

首版在 Windows 11、PowerShell 7 和 Node.js 22.22.2 环境验收。使用 PowerShell 语法，不在 Windows 命令中使用 Bash 引号、管道习惯或 heredoc。

## 工作区与修改

修改前确认当前目录、Git 仓库根和工作树状态，不覆盖使用者已有改动。默认使用当前工作树；只有使用者明确同意才创建 worktree，并提前说明合并和清理方式。

补丁路径使用相对仓库根目录的路径。同一种补丁失败最多重试一次；再次失败保留原始错误并改用其他方案。只有原始错误含明确拒绝访问或沙箱信息时才归类为权限问题。

## 实现

- 后台生命周期、项目检查、进程、日志、认证、MCP 和面板职责分离。
- 使用参数数组执行子进程，保留关键错误、状态转换和退出诊断。
- 所有入口复用后台状态，不在客户端建立独立服务注册表。
- 开发验证不自动执行真实 Java、Maven 或前端 build。按使用者确认的产品行为，普通启动可在产物缺少或过期时托管 Maven 编译及依赖准备；检查和导入保持只读。
- 面板不展示对使用者无帮助的内部实现细节；日志以纯文本显示。
- 外部代码和依赖保留来源及许可，不复制业务工程、个人配置或凭据。

## 验证与发布

自动测试隔离运行，不调用真实业务工程。验证记录明确区分自动测试、真实客户端验收和未覆盖项，不能把计划写成已通过结果。

MVP 完成前准备安装说明、许可证、第三方来源、安全策略及贡献模板。GitHub 创建、推送、公开发布和 npm 发布都作为后续单独确认的动作。
