# 首个 MVP 发布准备清单

本清单用于首个 MVP 本地验收和后续 GitHub 开源；尚未具备的能力保持未完成，不因为文档已存在就视作实现通过。

## 本地准备材料

- [x] 建立独立本地 Git 仓库及 main 分支。
- [x] 写明双客户端共享后台、面板和首版支持范围。
- [x] 准备 README、CONTRIBUTING、SECURITY、行为准则和 Issue／PR 模板。
- [x] 保留 Apache-2.0 许可证及来源版权。
- [x] 建立第三方来源、权限、配置和验证文档。
- [ ] 用户审阅并确认书面 MVP 设计。
- [ ] 根据已确认设计生成实施计划并确定执行方式。

## 产品验收

- [ ] 两个 MCP 客户端连接同一个后台，同一项目并发启动只有一个 JVM。
- [ ] 项目检查、JDK 选择、Profile／端口配置和已准备产物运行通过。
- [ ] 缺失或过期产物返回构建提示，不隐式执行构建。
- [ ] 状态和日志在两个客户端与网页一致，聊天结束服务继续运行。
- [ ] 面板自动滚动、暂停、搜索、复制及断线重连通过。
- [ ] 停止／重启只作用于托管 JVM，端口占用不会导致未知进程被终止。
- [ ] 凭据、Host、同源、票据、大小限制和日志文本渲染有负面测试。
- [ ] 后台异常遗留记录不会导致按旧 PID 接管、终止或重复启动。
- [ ] 自动测试通过并记录实际结果；CI 基于已有测试配置，不运行 Java／前端 build。
- [ ] 用户在可信工程上完成 Codex 启动、CC 查询和停止、面板看日志的交叉验收。

## 公开内容

- [ ] README 使用已验证命令，说明版本、环境要求和实际限制。
- [ ] Codex 与 CC 接入说明在干净目录中验证。
- [ ] 提供可公开的最小示例和脱敏截图，不包含业务项目。
- [ ] 已移植代码有准确来源修订、文件映射和修改声明。
- [ ] 依赖清单、锁文件、许可证及实际发行内容一致。
- [ ] 检查准备发布的整个 Git 历史和文件，清除凭据、内部路径、日志和个人配置。
- [ ] 补齐变更记录、已知问题和真实验收记录。
- [ ] 建立有效的私密漏洞报告及社区联络方式，更新 SECURITY。

## GitHub 发布动作

- [ ] 用户确认公开仓库名称、说明和可公开内容。
- [ ] 用户确认创建／关联 GitHub 远端并推送。
- [ ] 验证公开 README、许可证识别、模板和 CI。
- [ ] 在实际可用 MVP 对应提交上创建首个版本标签及发布说明。

公共 npm 包及平台扩展不属于首个 GitHub 源码发布的前提。
